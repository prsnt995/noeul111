# PG 검증 절차와 결과

검증일: 2026-09-28. 결제 서비스 코드와 테스트용 DB/PG 대역을 대상으로 합니다. 운영 DB·실제 토스 승인·정산 검증과 구분합니다.

## 1. 키 없이 반복 실행

```sh
npm run test:pg
npm run ci
npm run pg:lab
```

검증실: `http://127.0.0.1:5191/reset?scenario=normal`

`pg:lab`은 127.0.0.1에만 바인딩하고 .env를 읽지 않습니다. 실제 React 결제/관리자 화면과 실제 PG 서비스 모듈을 사용하되 SDK·토스 HTTP·DB만 테스트 대역입니다. 운영 빌드의 진입점에 연결하지 않았습니다. 테스트 데이터는 메모리에 있으며 서버 재시작 시 사라집니다. 인증/CSRF는 이 검증실에서 대체하므로 운영 보안 통합 테스트로 간주하지 않습니다.

| 시나리오 | 조작 | 기대 결과 |
|---|---|---|
| normal | 결제 → 관리자 환불 → 조회 → 3,000원 취소 → 7,000원 취소 | paid → partially_refunded → refunded, 잔액 0 |
| timeout | 결제 → 응답 불명 → 상태 다시 확인 | 중복 승인 없이 paid로 복구 |
| db-failure | 결제 → DB 저장 실패 → 상태 다시 확인 | 승인 1회, 조회 후 paid 저장 |
| refund-timeout | 결제 → 관리자 환불 | 새 환불 차단, 조회 복구 후 잔액 감소 1회 |
| cancel | 결제 | 실패 화면, 주문 식별자를 유지하여 상태 확인 가능 |
| disabled | 진입 | 결제 준비 실패, 결제 버튼 비활성화 |

`/lab/state`는 테스트용 주문과 호출 횟수를 보여줍니다. 시나리오 링크는 테스트 상태를 초기화합니다. 결제창/약관은 가짜 표시이며 토스 SDK 렌더링이나 카드사 앱 전환 테스트가 아닙니다.

## 2. 공식 문서 대조 기록

| 문서 | 코드 반영 |
|---|---|
| [API 레퍼런스](https://docs.tosspayments.com/reference) | 승인/조회/취소 경로, 주문·키·금액·통화 대조, DONE만 승인 완료, 부분취소 가능 여부 및 취소 거래 완료/금액/잔액 확인 |
| [v2 주문서형 연동](https://docs.tosspayments.com/guides/v2/payment-widget/integration) | widgets → setAmount → 결제수단/약관 렌더 → requestPayment → 서버 confirm |
| [인증·멱등키](https://docs.tosspayments.com/reference/using-api/authorization) | 시크릿 뒤 콜론을 포함한 Basic 인증, 승인/환불 고정 멱등키 |
| [타임아웃](https://docs.tosspayments.com/resources/glossary/timeout) | 60초 응답 대기를 고려해 전체 fetch 제한 65초 적용. 네트워크 오류는 복구 대기 |
| [웹훅](https://docs.tosspayments.com/reference/using-api/webhook-events) | PAYMENT_STATUS_CHANGED 수신 후 PG 재조회, DB 반영 실패는 503 |

토스 멱등키 유효기간은 15일이므로 DB의 중복 방지는 별도로 영속 유지합니다. 기간이 지났다는 이유로 새 키를 만들어 미확정 환불을 다시 요청하지 않습니다.

## 3. 테스트키 준비 후 실행

토스 공식 문서의 공용 테스트키로도 연동을 시작할 수 있으나 상점 결제내역 검증은 제한됩니다. 최종 인수는 로제나 상점의 짝이 맞는 테스트키로 진행합니다. 키를 코드/문서에 복사하지 않습니다.

1. DB 담당자가 README 저장소 계약과 공통 취소/만료 잠금 구현. 인증된 테스트 고객·관리자·1만원 주문 준비.
2. 서버 환경에 TOSS_CLIENT_KEY/TOSS_SECRET_KEY(둘 다 test 계열), PAYMENTS_ENABLED=true, 위젯/약관 variant, 복구 워커 설정. 실제 운영키는 이 단계에서 금지.
3. `npm run pg:preflight` 실행. 현재는 키/DB 미연결로 BLOCKED가 정상. PASS는 형식/존재 검사일 뿐 키 쌍 및 DB 원자성 증거가 아님.
4. 실제 서버 `npm run start`와 프런트 `npm run client` 또는 테스트 배포 실행. pg:lab을 사용하지 않음.
5. 테스트 고객으로 주문 생성 → `/checkout/toss?order=공개주문번호` 진입. 실제 토스 위젯/필수 약관/계약된 카드·간편결제 표시 확인.
6. 테스트 인증 → 성공 페이지. 서버 승인 200, DB 주문 paid, 원장 paymentKey/amount, outbox 고유 효과 및 토스 테스트내역 일치 확인.
7. 성공 URL 새로고침/두 탭 동시 호출 → PG 중복 승인과 중복 재고·포인트 효과 없음 확인.
8. 관리자 주문 상세에서 조회 → 3천원 부분취소 → 잔액 7천원 확인 → 잔액 전액취소. 토스 취소 transactionKey, DB 원장, 고객 상태를 각각 대조.
9. 장애 시나리오를 아래 순서로 재현. 브라우저 UI 성공만으로 PASS 기록 금지.

| 장애 | 검증 방법 / 합격 조건 |
|---|---|
| 인증 전 창 닫기 | 원치 않는 paid 없음, 예약 만료 정책대로 처리 |
| 인증 후 성공 페이지 전 닫기 | 임의 재승인 없음, 조회 결과에 따른 복구 또는 운영 검토 |
| 승인 직후 응답 차단 | 서버 승인 시도 영속, 재접속/워커로 복구, 승인 1회 |
| 승인 뒤 DB 실패 | 승인 잠금 유지, DB 회복 후 paid 1회 저장 |
| 환불 응답 차단 | 새 작업 차단, PG 취소 이력과 저장 의도 대조 후 복구 |
| 승인과 주문 만료 동시 실행 | 동일 DB 잠금 아래 한 경로만 승리, 돈·재고 불일치 없음 |
| 서버 강제 종료·재시작 | 영속 복구 큐 리스 재점유, outbox 중복 없음 |
| 웹훅 중복·역순·DB 오류 | 최종 상태 역행 없음, DB 실패 503, 재전송 후 복구 |
| 권한 | 타인 주문/일반 고객 환불/CSRF 누락/필요 MFA 누락 거절 |

웹훅은 외부에서 접근 가능한 HTTPS 테스트 서버 URL로 등록합니다. 국내 동기 결제는 PAYMENT_STATUS_CHANGED를 사용하며 해외 비동기 전용 CANCEL_STATUS_CHANGED를 국내 환불 완료 신호로 기다리지 않습니다. 가상계좌·해외 비동기·에스크로·환불계좌 필요 수단은 별도 구현 전 위젯에서 제외합니다. 일반 카드/간편결제도 실제 계약과 API 버전을 확인합니다.

## 4. 인수 결과 기록 양식

- 커밋 / 날짜 / 환경(모의·토스 테스트·운영):

## 기존 코드에서 바뀐 점

| 기존 HEAD | 현재 모듈 |
|---|---|
| Express 라우트에 PG와 DB 코드 혼재 | PG 서비스·저장소 계약·라우트·복구 워커 분리 |
| confirming 주문도 재선점, 예외 시 pending으로 되돌림 | 영속 claim 계약, 불명 상태 잠금 유지, 조회 복구 |
| 웹훅 먼저 200 반환 | 알려진 결제 PG 조회 및 DB 반영 후 응답 |
| 환불 멱등키가 HTTP 헤더 밖에 있음, 전체취소 위주 | 헤더 멱등키, 부분/전체취소, 잔액·취소 거래 검증 |
| 관리자 상태 변경으로 유료 주문 취소 가능 | 유료 주문은 PG 환불 경로로만 취소 |
| 실패 시 비원자적 만료 fallback | RPC 실패 시 상태 유지/운영 알림 |
| 정적 소스 검사 중심 | 상태를 가진 테스트 대역으로 생명주기 회귀 + 브라우저 검증실 |

배포 시 프런트 문서의 COOP/CSP가 토스 팝업/스크립트/iframe을 차단하지 않는지 공식 인증·헤더 문서와 대조하세요. 현재 API의 Helmet 설정만으로 프런트 배포 헤더까지 검증된 것은 아닙니다.

## 2026-09-29 로제나 상점 테스트 연결

- 콘솔 MID `rozenazay6`: 심사중, 계약일 `-`. 운영 결제 준비 완료 아님.
- 주문서형·결제창형 테스트 키 쌍을 Git 제외 `.env.pg-test`에 저장(파일 권한 600). 일반 앱의 `PAYMENTS_ENABLED=false` 유지.
- `npm run pg:sandbox`: 실제 토스 SDK/API + 테스트 전용 메모리 저장소. 127.0.0.1:5192만 리스닝. 운영/스테이징 서버에 배포하지 않음.
- 실제 위젯 `DEFAULT` 및 약관 `AGREEMENT` 렌더링, 국민카드 테스트 인증창 연결 확인.
- 테스트 주문의 Basic 인증 조회: HTTP 200, `READY`, 10,000원, 테스트 MID `trozenazay6`. 승인 성공 증거 아님.
- 사용자 토스페이 인증 완료 후 실제 테스트 API 승인 확인: HTTP 200 / DONE / 10,000원 / 간편결제(토스페이). 임시 메모리 주문 paid와 대조함.
- 실제 API 3,000원 부분취소(DONE, 잔액 7,000원) 및 7,000원 잔액취소(DONE, 잔액 0원) 확인. 토스 개발자센터 테스트 결제내역과 대조함.
- 마지막 응답은 PARTIAL_CANCELED + 잔액 0원. 실행 중이던 테스트 저장소는 partially_refunded로 표시했으므로 잔액을 함께 보는 refunded 매핑으로 수정하고 회귀 검증함. DB 담당자도 원본 PG 상태와 내부 주문 상태를 구분해야 함.
- 실제 DB 저장/재시작 복구/외부 웹훅/배포는 미검증.
- 전체 `npm run ci` 통과: 타입검사, lint 오류 0(경고 118), 100개 테스트, 빌드. 첫 sandbox 실행에서 HTTP 테스트의 listen EPERM이 발생하여 정상 실행 권한으로 재검증함.
- 준비 검사: `DOTENV_CONFIG_PATH=.env.pg-test npm run pg:preflight`. 키 형식은 PASS, 비활성화와 미구현 DB 메서드는 BLOCKED가 정상.
